# WM_CHECKLIST

Адаптивный веб-чеклист и трекер покупок для ПК и мобильных устройств на чистом HTML/CSS/JS без серверной части, сборщиков и внешних зависимостей.

**Демо (GitHub Pages):** https://whtmst.github.io/checklist/

> **Приватность:** в этом репозитории лежит только чистый интерфейс. Все записи хранятся локально в `localStorage` вашего браузера, а при желании синхронизируются с **вашим собственным** скрытым GitHub Gist. Пользователи полностью изолированы друг от друга.

## Возможности

- **Несколько вкладок-списков и управление ими** — создавайте отдельные списки (например, «Основная», «Курьер», «Дом») с независимым подсчётом итогов. Через кнопку **`•••`** справа от панели вкладок открывается менеджер вкладок: создание новых списков, изменение их порядка стрелками `↑`/`↓` или перетаскиванием за `⋮⋮`, переименование и удаление. Категории и отдельные карточки можно **переносить или копировать** между вкладками.
- **Категории, порядок и массовое сворачивание** — сворачивайте и разворачивайте любую категорию кликом по всей её шапке, а кнопкой **`−` / `+`** на панели инструментов сворачивайте или разворачивайте сразу все категории на вкладке. Через кнопку **`•••`** на панели инструментов доступен менеджер категорий: сортировка стрелками `↑`/`↓` или перетаскиванием за `⋮⋮`, переименование, перенос/копирование и удаление.
- **Компактные карточки и фильтрация** — 5 уровней приоритета (`КРИТИЧНО`, `ОЧЕНЬ ВАЖНО`, `СРЕДНЕ`, `ЖЕЛАТЕЛЬНО`, `МОЖНО ОБОЙТИСЬ`), выбор магазина (`Местный рынок`, `Birmarket`, `Temu`, `Ozon` или свой вариант), кликабельный бейдж-ссылка магазина (`↗`), поиск и фильтры по статусу (включая «Только в кредит / рассрочку»), приоритету и магазину.
- **Выдвижная панель просмотра карточки** — открывается справа на ПК и шторкой снизу на мобильных устройствах. Строки в заметке формата `Ключ: Значение` автоматически раскладываются в аккуратную таблицу характеристик.
- **Удобный ввод без потерь** — автосохранение черновика новой позиции в рамках сессии, кнопка «Очистить», защита от случайного закрытия несохранённой формы и авторасширение поля заметки под текст.
- **Единый учёт кредитов, рассрочек и карты (кнопка «Кредиты» в шапке):**
  - 4 типа оплаты в долг: **`Рассрочка`** (таксит 0%), **`Ninja`** (разделение с %), **`Льготный период`** (с датой «Оплатить до» и счётчиком оставшихся дней) и **`Свой вариант`**, а также фильтрация списка долгов по типу.
  - Оформление как на 1 товар, так и на **пачку товаров из разных вкладок** (в итоги каждой вкладки идёт её честная пропорциональная доля без двойного счёта).
  - Ручной ввод реального ежемесячного платежа и итоговой суммы под график банка; автоматический расчёт переплаты, даты окончания, оставшихся платежей и полоски прогресса.
  - Справочные поля **«Лимит карты»** (занято / свободно) и **«Доход / мес»** (процент кредитной нагрузки и остаток после платежей).
- **Светлая и тёмная темы + локальный шрифт** — тёмная тема по умолчанию, все цветовые переменные `:root` вынесены в `css/tokens.css`, адаптивная шапка с компактными иконками на мобильных экранах. Подключён локальный вариативный шрифт **Finlandica** — интерфейс работает полностью офлайн.
- **Локальный бэкап** — экспорт и импорт резервной копии в `.json`, копирование JSON в буфер обмена и полная очистка данных.

## Как работает синхронизация (Secret GitHub Gist)

Синхронизация между ПК и телефоном работает напрямую через GitHub API без промежуточных серверов:

1. **Автоотправка (Auto-Push):** после любого изменения данные мгновенно сохраняются локально, а через **1.5 секунды** после последнего действия отправляются в скрытый Gist (`wm-checklist-data.json`).
2. **Бережная автоподгрузка (Auto-Pull):** при открытии страницы, возврате на вкладку (разблокировке телефона) и раз в **60 секунд** (только пока вкладка активна на экране) приложение проверяет обновления с заголовком `ETag` (`If-None-Match`). Если изменений нет, GitHub отвечает `304 Not Modified` и **не расходует лимит GitHub API** (0 из 5 000 запросов в час).
3. **Защита от перезаписи:** локальное состояние обновляется только если версия в Gist новее (`updatedAt`), а при необходимости можно принудительно обновить данные кнопкой синхронизации в шапке.

## Настройка синхронизации на своих устройствах

1. На GitHub откройте **Settings → Developer settings → Personal access tokens → Tokens (classic)** → **Generate new token (classic)**.
2. Укажите название (например, `wm-checklist`), срок действия и отметьте **только одно право — `gist`**.
3. Скопируйте полученный токен (`ghp_...`).
4. **На первом устройстве (ПК):** откройте https://whtmst.github.io/checklist/, нажмите **Настройки**, вставьте токен → **Сохранить настройки** → **Отправить в GitHub ↑** (создастся скрытый Gist, его `Gist ID` пропишется автоматически).
5. **На втором устройстве (телефон):** откройте ту же ссылку, зайдите в **Настройки**, вставьте тот же токен → **Найти мой Gist** → **Загрузить с GitHub ↓**.

> Токен сохраняется только в `localStorage` вашего браузера и никогда не попадает в код репозитория. При перевыпуске (Regenerate) токена данные в Gist не теряются — достаточно вставить новый токен в настройках.

## Структура проекта

```text
index.html        — разметка страницы, выдвижной панели, менеджеров вкладок/категорий и модальных окон
assets/
  fonts/
    Finlandica-VariableFont_wght.ttf — локальный вариативный шрифт интерфейса
css/
  tokens.css      — подключение шрифта и цветовые переменные (:root) для тёмной и светлой тем
  styles.css      — адаптивная вёрстка для ПК и мобильных устройств
js/
  config.js       — справочники (приоритеты, магазины, типы долга) и расчёт сроков
  storage.js      — localStorage, CRUD, сортировка и перенос вкладок/категорий, единый реестр кредитов и авто-миграция
  sync.js         — синхронизация через Secret GitHub Gist (ETag / Auto-Pull) и JSON-бэкапы
  render.js       — безопасная DOM-отрисовка списка, карточек, панели просмотра, менеджеров и сводки кредитов
  app.js          — обработчики событий, drag-and-drop, массовое сворачивание категорий, модалки, черновики, фильтры и тема
```

## Запуск собственной копии на GitHub Pages

1. Сделайте форк или скопируйте файлы в корень своего репозитория.
2. Включите публикацию в **Settings → Pages → Build and deployment**:
   - **Source:** `Deploy from a branch`
   - **Branch:** `main` / `/ (root)` → **Save**.
3. Через 1–2 минуты приложение станет доступно по адресу `https://<ваш-логин>.github.io/<имя-репозитория>/`.
